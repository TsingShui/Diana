# Nested loop exits

## Input and provenance

`LoopExits.java` explains the independently authored `LoopExits.smali`. No
third-party program or identifying corpus material is used. The Smali is the
assembly input; Java is not compiled to prepare this case. Original owner:
`Lfixture/LoopExits;`.

| Method | Prototype | Trigger or guard |
|---|---|---|
| `nestedBreak` | `(III)I` | Inner match work lies in the enclosing backedge core, before the inner predicate's normal follow. |
| `outerBreak` | `(III)I` | A private exit reaches the enclosing predicate's shared normal follow. The shared return stays outside both loops. |
| `outerContinue` | `(III)I` | Private match work updates the row and returns to the enclosing header, not the inner normal follow. |
| `sharedExit` | `(III)I` | Two original exits enter the same match work; neither corridor is private. |
| `siblingLoop` | `(II)I` | A loop exit enters another loop's core, which does not enclose the first. |
| `protectedExit` | `(III)I` | The match call has a local RuntimeException handler; its protection owner cannot be absorbed as a plain corridor. |

`mark(I)V` is an original native declaration in the DEX. Scenario semantics bind
it to a host that records its argument and returns normally, except for the
explicit throwing scenario below. No external declaration input is given to Diana.

## Preparation and inspection

Assemble with a locally available Smali tool and leave generated bytes ignored:

```sh
mkdir -p .cache/fixtures/nested-loop-exits
java -cp "$SMALI_CLASSPATH" org.jf.smali.Main assemble --api 24 \
  -o .cache/fixtures/nested-loop-exits/classes.dex \
  fixtures/nested-loop-exits/LoopExits.smali
cargo run -p diana-decomp --example dbg_shell --locked -- \
  --dex .cache/fixtures/nested-loop-exits/classes.dex \
  --exec '{"cmd":"p6-all","details":true}' \
  --exec '{"cmd":"p9-all","text_only":true}'
cargo nextest run --locked -p diana-decomp
```

Actual preparation used Smali 2.5.2, `--api 24`, on OpenJDK 21.0.12.1. Those
versions record the environment, not a per-fixture version requirement. Inspect
class/method identities in the assembled image rather than reusing table indexes
from another build. Missing or stale input is a preparation failure; reassemble
before running the structural checks.

## Independent scenarios

Initial local counters and total are zero as stated in both sources. There is no
shared mutable scenario state. Each trace starts empty. Inputs here avoid integer
overflow and bound the loops. Trace notation lists calls in execution order.

For `nestedBreak`, a hit executes its mark and total update before the inner
break; outer row advancement still runs. Normal inner exhaustion does not execute
the match work. `outerBreak` skips row advancement after the hit.
`outerContinue` executes its private row advancement exactly once before the next
outer test. `sharedExit` executes the shared mark once regardless of which match
link is taken. `protectedExit` adds no ten after a thrown mark call.

## Structural checks and evidence limits

`crates/diana-decomp/src/p6/compose/loop_exits_tests.rs` obtains each method through
ordinary `Engine::analyze_method`, resolving its original owner/name/prototype.
Six test-only checks inspect delivered P6 ownership and P9 text/origins. They
require the two private break cases to have no goto, require the enclosing
follow/continue target to stay outside the inner corridor, and preserve the
shared, sibling and local-handler refusals. The mark invocation retains one
printed occurrence and one original-operation/PC anchor in each method.

On `80dae69` with only these tests added, the three private-corridor checks fail
because the expected private exit is absent; the three guard cases pass. With
the P6 enclosing-boundary repair in the working tree, all six structural checks
pass on the same assembled input. `outerContinue` still contains an explicit
goto inside the inner body; the check covers its corridor boundary and original
enclosing Continue, not a fully structured branch.

These checks catch the ownership/shape defect, not a known behavioral mismatch.
Not run: independent execution of the final emission plan against the scenario
table. The EVOLUTION behavioral executor and admitted semantic regression suite
remain unimplemented; these structural passes are not behavioral acceptance.
